# REQUISITOS FORMAIS — Gerir Manutenção (SGM)

## Requisitos Funcionais
|ID| Descrição |
|--|-----------|
| RF01 | Cadastro de Equipamentos: O sistema deve permitir o registro de máquinas industriais, incluindo nome, modelo, número de série, localização na fábrica e criticidade, selecionada a partir de uma lista fechada: Alta, Média ou Baixa. |
| RF02 | Registrar Manutenção Corretiva: O sistema web deve permitir que o técnico registre uma manutenção corretiva informando: máquina (selecionada por código ou nome), descrição da falha (até 500 caracteres), causa identificada, indicação de parada de produção, leitura do horímetro, peças trocadas (selecionadas de uma lista, com quantidade) e data/hora automática. |
| RF03 | Registrar Manutenção Preventiva: O sistema web deve permitir que o técnico registre uma manutenção preventiva com: checklist de itens verificados (específico de cada máquina, cadastrado pela Equipe Administrativa), marcação de cada item como Verificado ou Não aplicável, leitura do horímetro, data/hora automática e observações complementares. A conclusão é bloqueada enquanto houver item obrigatório sem resposta. |
| RF04 | Agendamento Automatizado: O sistema deve permitir a programação de planos de manutenção preventiva por máquina, com periodicidade Diária, Semanal, Mensal, Trimestral, Semestral ou Anual. A cada preventiva concluída e aprovada, o sistema calcula a próxima data a partir da periodicidade definida e gera a nova ordem de serviço preventiva. O horímetro (horas de operação) é informado manualmente pelo técnico no registro da manutenção, apenas para fins de histórico. |
| RF05 | Painel de Indicadores (Dashboard): O sistema deve exibir indicadores de desempenho (MTBF e MTTR) e o status atual de disponibilidade das máquinas, com atualização automática a cada 60 segundos. |
| RF06 | Alertas de Manutenção: O sistema deve enviar notificações automáticas para os técnicos e supervisores quando uma manutenção preventiva estiver a menos de 24 horas do prazo (alerta de proximidade) ou quando estiver atrasada há mais de 24 horas (alerta de atraso). |
| RF07 | Geração de Relatórios: O sistema web deve permitir que o Gestor ou Supervisor consulte, em tela, relatórios mensais de histórico de falhas por equipamento e de consumo de peças (quantidades utilizadas, registradas nas baixas de estoque), por período e por máquina, sem cálculo de custos financeiros. |
| RF08 | Consultar Histórico da Máquina: O sistema web deve permitir que o técnico consulte, por meio de busca por código ou nome parcial, o histórico completo de intervenções (corretivas e preventivas) de uma máquina específica, ordenado da mais recente para a mais antiga. |
| RF09 | Visualizar Tarefas da Semana: O sistema web deve exibir ao técnico uma lista de todas as tarefas preventivas agendadas para a semana, organizadas por data de vencimento (da mais próxima para a mais distante) |
| RF10 | Dar Baixa em Peças no Estoque: O sistema web deve permitir que o técnico dê baixa em peças utilizadas durante a manutenção, selecionando-as de uma lista pré-carregada e informando a quantidade, reduzindo automaticamente a quantidade no estoque interno do sistema. |
| RF11 | Distribuir Ordens de Serviço: O sistema web deve permitir que o supervisor atribua ordens de serviço (preventivas ou corretivas) a técnicos específicos, definindo: máquina, tipo, descrição, prioridade (alta, média, baixa) e prazo de entrega. |
| RF12 | Aprovar Ordens de Serviço: O sistema web deve permitir que o supervisor aprove ou rejeite ordens de serviço registradas pelos técnicos antes da consolidação no histórico, exigindo justificativa obrigatória em caso de rejeição. |
| RF13 | Alerta de Estoque Mínimo: O sistema deve verificar automaticamente a quantidade em estoque após cada baixa de peça (RF10) e enviar uma notificação ao perfil Administrativo e ao Supervisor quando a quantidade atingir ou ficar abaixo do estoque mínimo cadastrado para aquela peça. A notificação deve conter: nome da peça, código, quantidade atual e estoque mínimo definido. Não deve ser gerado novo alerta para a mesma peça dentro de 24 horas. |
| RF14 | Monitorar Status da Equipe: O sistema web deve exibir ao supervisor um painel com o status de cada técnico cadastrado, indicando se está "Ocupado" ou "Disponível", com atualização automática a cada 60 segundos. O status "Ocupado" é definido automaticamente quando o técnico inicia uma ordem de serviço; o status "Disponível" é definido automaticamente quando o técnico finaliza ou quando não possui nenhuma ordem de serviço em andamento. O supervisor pode alterar manualmente o status de qualquer técnico. |
| RF15 | Identificar Máquinas Críticas: O sistema web deve permitir que o gestor visualize um ranking com as 10 máquinas que registraram o maior número de falhas no período selecionado, exibido em ordem decrescente de ocorrências. O gestor pode filtrar o ranking por período (30, 90 ou 180 dias). Cada entrada do ranking deve exibir o nome da máquina, o número total de falhas no período e o MTBF atual. O gestor pode clicar em uma máquina para acessar seu histórico detalhado de intervenções. |
| RF16 | Monitorar Produtividade da Equipe: O sistema web deve exibir ao gestor gráficos comparativos entre o total de tarefas planejadas e o total de tarefas concluídas no período selecionado, calculando automaticamente o percentual de conclusão. O gestor pode filtrar os dados por período (semana ou mês), por equipe ou por técnico individual. |

## Requisitos não funcionais
|ID| Descrição |
|--|-----------|
| RNF01 | Responsividade: A interface web deve ser totalmente responsiva, adaptando-se nativamente a navegadores de tablets e smartphones sem apresentar sobreposição de elementos visuais ou exigir rolagem horizontal da tela. |
| RNF02 | Operabilidade do Registro de Falhas: O fluxo de 'Abertura de Registro de Falha' deve ser concluído com sucesso em menos de 5 cliques. O contador inicia na página inicial e termina na visualização da mensagem de confirmação de envio. |
| RNF03 | Segurança de Acesso e Validação de dados: O acesso usuários na plataforma deve ser autenticado e restrito a usuários que já são cadastrados seguindo as regras estabelecidas para validação de dados e de tipos de usuários (Técnico, Supervisor, Gestor, Administrativo e Administrador do Sistema). |
| RNF04 | Qualquer página do sistema deve carregar em até 3 segundos em conexões de internet com velocidade de download igual ou superior a 10 Mbps. |
| RNF05 | Disponibilidade do Sistema: O sistema deve estar disponível 99,5% do tempo no horário de produção (06h às 22h), exceto durante janelas de manutenção programada comunicadas com 48 horas de antecedência. |
| RNF06 | Compatibilidade com Navegadores: O sistema deve ser compatível com as versões atuais dos navegadores Chrome, Firefox, Edge e Safari. |
| RNF07 | Acessibilidade Web: O sistema web deve seguir as diretrizes de acessibilidade WCAG 2.1 nível AA para contraste, navegação por teclado e compatibilidade com leitores de tela. |
| RNF08 | Autenticação de Usuários: O sistema deve autenticar usuários via login e senha, com suporte a autenticação em dois fatores (2FA) obrigatória para os perfis de Supervisor, Gestor e Administrador do Sistema. |
| RNF09 | Conformidade com a LGPD: Os dados pessoais dos usuários (técnicos, supervisores, gestores) e informações de equipamentos devem ser armazenados e processados em conformidade com a Lei Geral de Proteção de Dados (LGPD), garantindo direito de acesso, retificação e exclusão. |
| RNF10 | Controle de Acesso por Perfil (RBAC): O acesso às funcionalidades do sistema deve ser restrito estritamente ao perfil do usuário, conforme os seguintes papéis de negócio: Técnico, Supervisor, Gestor e Administrativo. Adicionalmente, o sistema possui o perfil técnico **Administrador do Sistema** (superusuário), com acesso total a todas as funcionalidades e exclusividade na gestão de contas de usuário. |
